# MD Card

Генератор сайтов для малого бизнеса (барбершоп, репетитор, мастер маникюра, фотограф) из Markdown-DSL. Это проект выпускной квалификационной работы (ВКР).

**План работ — `PLAN.md`.** Перед началом любой задачи прочитай в нём нужный этап целиком. Пункты «Готово, когда…» — критерии приёмки: в конце этапа проверь каждый и отчитайся.

## Стек
- React 19, Vite, TypeScript, Tailwind 4
- Supabase: Postgres, Storage, Auth, Edge Functions (Deno). Проект `tscyshpimbgoelliqhxu`, регион eu-central-1
- Vercel — хостинг приложения и деплой сгенерированных сайтов
- GigaChat API — клиент в `supabase/functions/_shared/gigachat.ts` (проверен, работает из Edge Functions; нужен секрет `GIGACHAT_CA_CERT_B64` с сертификатами НУЦ Минцифры из `certs/`)

## Правила
- `src/dsl/` — чистый TypeScript без React и браузерных API: используется и во фронтенде, и в Edge Functions.
- Любое изменение БД — только новой миграцией в `supabase/migrations/`. Новые таблицы — сразу с RLS и политиками.
- Сгенерированные сайты — полностью статические: никаких форм и серверной части, связь с бизнесом только через телефон и контакты в мессенджерах/соцсетях.
- Секреты (Vercel, GigaChat, service role) — только в секретах Supabase (`npx supabase secrets set`), никогда в `VITE_*` переменных и никогда в коде или git.
- Сообщения для пользователя — на русском, понятные человеку без технического опыта.
- Новый блок DSL = схема + парсер + валидация + компонент во всех 4 темах + тесты + пример в README.
- После изменений парсера/валидатора: `npm test`. Перед коммитом: `npm run build && npm run lint`.
- Работаем маленькими шагами: один логический кусок — один коммит с понятным сообщением на русском.
- В конце каждого шага и этапа объясни, **как увидеть результат своими глазами**: что запустить (`npm run dev`, `npm test`, `npx vitest --ui`), куда нажать, какой текст вставить в редактор и что должно получиться. Если изменения внутренние и в интерфейсе их не видно — покажи на примере через тесты.
- После завершения этапа отметь его в `PLAN.md` как выполненный и допиши раздел «Заметки для ВКР»: какие решения приняты и почему, какие были проблемы. Это материал для главы 3.

## Про пользователя
Автор — студент, работает на macOS. Всё, что нужно сделать вне кода (секреты, деплой функций, настройки в панелях Supabase/Vercel/Studio), объясняй по шагам с готовыми командами для терминала macOS и говори, что должно получиться. Ключи и пароли не проси вставлять в чат — пусть вводит сам в терминале.
